How to use Design System Viewer

Your tokens → categorized gallery → live preview → compare → export. All local, no build needed.

1
Add a system — Add system
Paste bare --token: value; lines (no :root needed). Or drag & drop a .css file, or fetch from URL. Use Fill template for the full-token skeleton. Last write wins.
2
Inspect — Tokens tab
Swatches (color), type specimens, bars, cards. Filter, Show missing, Schema & Contrast WCAG. Click to copy, Update button or double-click to edit a token.
3
Preview — real components
~35 Radix primitives (Forms, Overlays, Navigation…) + 15 screens (Login, Pricing, Dashboard, Chat…) render with your tokens via var(--token) + fallback. Each system shows in its own colors — no global theme switch, the system's own --color-bg is the background.
Your token names must match the schema exactly (--color-accent, --space-4, …) — the Tokens gallery groups any name by pattern, but Preview only ever reads the canonical schema ones. A differently-named token shows fine in the gallery and does nothing here.
4
Compare — side-by-side or diff
Component: same component in 2–4 systems, each column isolated. Token diff: table grouped by category, colour chips, only differences toggle. For updates, use Tokens → Update on the selected system.
5
Manage & export — in the toolbar
Add system (top right) creates one. Everything for the system you are looking at — add tokens, schema view, export CSS/JSON, delete — lives in the toolbar above the gallery.
Tips
• Value warnings (unitless, bad hex, unknown colour, undefined var) never block save.
• Coverage bar shows present/expected vs schema reference.
• All data lives in systems/*.json on disk — reload after restart.
